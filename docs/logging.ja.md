# ログとクラッシュレポート

drawDB Desktop は、ユーザー環境で起きた問題を再現前に調査できるよう、診断ログを
ローカルファイルへ記録します。ネットワークへの送信は一切行いません。

## ログの場所

**File > デスクトップファイル > ログフォルダを開く**（macOS では
**ヘルプ > ログフォルダを開く** も可）で開けます。フォルダは次のとおりです。

| OS | フォルダ |
| --- | --- |
| Windows | `%LOCALAPPDATA%\app.drawdb.desktop\logs` |
| macOS | `~/Library/Logs/app.drawdb.desktop` |
| Linux | `~/.local/share/app.drawdb.desktop/logs` |

現在のファイルは `drawdb.log` です。2 MiB でローテーションし、直近 5 世代を保持する
ため、フォルダ全体はおよそ 12 MiB 以下に収まります。

## 記録される内容

- Rust 側の警告・エラー（例: 最近使ったファイルの保存失敗、ファイルアクセス権の
  付与失敗）。リリースビルドは `info`、開発ビルドは `debug` レベル。
- Rust の panic（メッセージ、発生箇所、バックトレース）。リリースビルドはシンボルを
  strip しているためバックトレースはアドレスのみの場合がありますが、メッセージと
  発生箇所は必ず記録されます。
- フロントエンドの `console.error` / `console.warn`、未捕捉例外、未処理の Promise
  rejection（`tauri-plugin-log` 経由）。

## プライバシーポリシー

- ダイアグラムの内容、テーブル・カラム定義、SQL / Excel ファイルの内容は記録しません。
- メッセージ中のホームディレクトリは `~` に置換します（例:
  `/home/alice/db/shop.ddb` → `~/db/shop.ddb`）。アカウント名はディスクに残りません。
  ファイルエラーの調査に必要なためパスの残りは保持します。公開 issue に添付する前に
  内容を確認してください。
- フロントエンドの 1 レコードは 4,000 文字で切り詰めます。

## クラッシュレポートサービス

リモートのクラッシュレポート（Sentry 等）は意図的に同梱していません。アカウント、
DSN、プライバシーポリシー、アプリ内のオプトイン同意 UI が前提になるためです。それらが
整うまでは、不具合報告にローカルのログファイルを添付してください。
**ヘルプ > 不具合を報告** で GitHub の issue 作成画面を開けます。
